# ModHub

Degrees of Lewdity (DoL) 模组管理套件，基于 ModLoader 2.x 运行时与 TweeReplacer 补丁架构。

市场卡片跨行统一高度，按当前列表中最高的卡片自适应，来源与底部操作对齐；窄屏使用等高单列布局，长内容可完整阅读。双语卡片使用并排语言按钮，只显示当前语言的版本、说明与来源。

v1.4.0 同版补充可复用语言变体：目录明确声明的同一模组只显示一张市场卡片，直接切换简体中文或 English，再点击带语言名称的按钮选择对应版本，无需重复选择语言。切换按钮分别显示真实安装状态，版本与额外前置跟随所选语言；卡片重绘保留本次选择，安装期间暂停切换。普通更新与批量更新保留已安装语言，两个语言不同步发布时也分别判断。

安装另一语言时须明确确认保留旧语言包并继续，取消后可到模组管理处理旧包；不会静默卸载或禁用。两种语言均已安装时分别显示并更新。LNN 战斗对手状态显示的简中另行核验 ModI18N 必需前置，英文不附加该要求。独立包 ID、技术名、来源与摘要保留，旧客户端仍读取独立条目，未声明变体的同仓库模组不会自动合并。目录字段和兼容边界见 [语言变体契约](LANGUAGE_VARIANTS.md)。

v1.4.0 新增独立【帮助中心】页签，按“描述问题 → 确认分析 → 查看方案 → 重载验证”引导 AI 辅助修复。游戏侧栏入口统一显示为【ModHub】。点击【获取帮助】后，先在本机整理日志与分析材料，再由玩家确认发送；日志中的首错与关联模组也可直接带入帮助流程。AI 连接设置使用独立入口，可随时填写地址、模型和密钥，返回后继续原问题。

帮助中心参考 Windows“获取帮助”的信息组织，可选择日志生成的【猜你想问】直接继续，也可自行描述问题；文件选择等技术选项默认收起。常见问题可直接展开本地排查与配置修复；已确认的问题可在预览并确认后启用符合要求的已安装前置，或整理已启用模组的加载顺序。配置与代码修复前均强制保存还原点，保存后回读核验，仍需重新载入验证实际效果；图片异常可尝试刷新现有图像缓存与画布。自有 AI 修复不依赖枫叶框架或调试模式，本地检查与报告不读取游戏存档或自动上传。

v1.3.4 增加样式完整性检查。在启动完成、打开管理面板或显示确认框时，若 ModHub 样式缺失或未生效，从当前已加载包的早期快照恢复完整样式，保持基础、市场和最终覆盖的顺序；正常加载不重复注入，不修改其他模组样式。检查不依赖网络或秋枫白桦框架。

市场最新版本移除附加的括号说明，保留原始版号或发布标签。重载提示以红色加粗强调未存档进度可能丢失，以金色加粗提示先存档；普通导入与框架重载均保留同一提醒。

## 下载与安装

从 [GitHub Releases](https://github.com/JohnLiao501/ModHub/releases) 的 Assets 下载正式附件 `ModHub-v<版本号>.zip`，在游戏原生模组管理器或 ModHub 的【导入模组】中直接选择该 ZIP。

GitHub 自动提供的 `Source code (zip)` 用于源码开发，通常名为 `ModHub-<版本号>.zip`，其 `boot.json` 位于 `ModHub-<版本号>/src/` 内，不能直接作为模组安装包导入。若原生管理器提示 `bootJson文件 [boot.json] 无效`，请检查所选 ZIP 根目录是否包含 `boot.json`，并重新下载正式安装附件；只有重命名 ZIP 不会改变目录结构。

## 源码命名

- `src/javascript/modhub-manager.js`：管理、持久化、导入、重排保存与公共入口。
- `src/javascript/modhub-style.js`：早期保存本包样式快照，按加载阶段检查完整性，仅在缺失时恢复。
- `src/javascript/modhub-dialog.js`：Toast、确认框、提示框与公共圆环加载状态；页签模板在初始化前显示加载占位。未知进度以自有帧字体保留 Windows 11 风格圆弧伸缩与旋转，从圆点开始，字体就绪后仅通过 CSS 变换播放，加载失败时保留原有 SVG 动画。下载比例与批量已完成项使用 Determinate 圆环；无法测量安装内部百分比时仍显示等待动画。
- `src/javascript/modhub-restore.js`：操作前还原点、包体去重、原子恢复与加载期救援。
- `src/javascript/modhub-restore-panel.js`：时间点还原面板、保护设置、历史管理与只读救援流程。
- `src/javascript/modhub-drag.js`：长按、桌面与触摸拖拽、边缘自动滚动；重排结果由管理器保存。
- `src/javascript/modhub-beauty.js`：可选美化插件的自动启用、列表、排序与保存；操作锁和失败恢复由管理器统一处理。
- `src/javascript/modhub-readme.js`：模组说明、Markdown、徽章与内置图片。
- `src/javascript/modhub-log.js`：日志诊断、筛选、截图、启动自检与错误原文获取帮助入口。
- `src/javascript/modhub-ai-package.js`：受限普通 ZIP 读取、校验、SHA-256 与选定文本替换，不执行包内代码。
- `src/javascript/modhub-ai-repair.js`：所选源码与诊断材料、兼容 API 请求、代码改动校验及受控应用，通过 `window.modHubAiRepair` 提供接口。
- `src/javascript/modhub-help.js`：按现象排查、已确认配置问题的变更预览与修复、图像刷新、求助报告及自有 AI 修复的分步界面，通过 `window.modHubHelp` 提供接口。
- `src/javascript/modhub-market.js`：市场目录、依赖规划与下载安装。每次进入游戏首次获取在线目录并在本机保存最近成功目录，后续切页复用本轮缓存；失败时保留原有离线回退，手动【刷新市场】重新获取目录及本地资料。本地包体仅在首次进入或状态变化后重新扫描，安装前仍实时核验。目录读取共用在途请求并限制等待时间；扫描逐包让出执行时间，离开页签后停止后续任务，已经落盘的修复仍完成缓存同步。
- `src/javascript/modhub-market-spells.js`：多来源获取与逐包适配说明、咒语配方的独立缓存、搜索、文本详情与原文复制，通过 `window.modHubMarketSpells` 提供接口。
- `src/javascript/modhub-market-versions.js`：历史发布、游戏版本识别、兼容证据和推荐排序，通过 `window.modHubMarketVersions` 调用市场公共接口。
- `src/javascript/modhub-market-install.js`：共用选版、包体预检、历史前置和安装确认，通过 `window.modHubMarketInstaller` 协调安装。
- 样式按 `modhub.css`、`modhub-market.css`、`modhub-overrides.css` 顺序加载，分别保留公共与响应式样式、市场样式、跨页面提示及最终覆盖；调整时须保持层叠顺序。
- 样式守卫、弹窗、还原面板与还原引擎先按顺序由 `scriptFileList_inject_early` 注入；普通脚本依次加载管理器、拖拽、美化、说明、日志、市场、多来源与咒语配方、历史版本、市场安装、AI 包体处理、AI 修复核心与帮助中心。跨文件调用使用显式的 `window.modHub…` 接口。
- 自有 JavaScript 接口和 DOM ID 使用 `modHub` 前缀，CSS 类使用 `modhub-`，常量使用 `MODHUB_`，日志使用 `[ModHub]`。
- 本地设置与缓存使用 `modhub_` 键，缺失时兼容读取旧版 `dol_opt_` 键，新设置优先且不删除旧数据。
- 市场中“原版优化”模组的真实名称、技术标识与仓库地址保持原样。

## 自动化测试

运行 `node src/test-smart-sort.js`，依次执行 `tests/` 下的管理、还原、市场目录、诊断与冲突、帮助中心、安装流程及交互回归用例。`tests/helpers.js` 提供共用沙箱与源码读取工具；样式检查按 `boot.json` 的加载顺序读取全部 CSS。

圆环帧字体使用 Python 标准库生成；运行 `python tests/modhub-progress-font.py <QA输出目录> src/stylesheet/modhub.css` 可重建字体并核验 CSS 内嵌字节。生成物仅写入指定 QA 目录。

## 帮助中心排查与修复

先描述遇到的问题并点击【获取帮助】，确认本机整理的分析范围与 AI 服务后再发送。也可展开常见问题使用本地检查与修复；检查结果展示可读取的声明、问题依据与对应操作。确认配置修复前可查看将启用的前置或将保存的加载顺序，取消不会执行变更。修复前必须成功建立还原点，并再次核对原配置与包体；检查后发生变化时拒绝使用旧结果。保存后回读验证成功，仅表示配置已经保存，需先保存游戏进度，再重新载入核验实际效果。

前置修复仅启用已经安装、提供者唯一且版本满足要求的模组。顺序修复按真实名称和兼容别名整理已启用模组，不改变美化覆盖顺序；版本要求无法确认、多个提供者或循环依赖不会自动处理。缺少安装包时仍转到市场原有安装流程。配置检查不会按一条日志擅自禁用模组或认定全部模组兼容；代码修改使用下述独立的 AI 预览确认流程。

图片异常可刷新实际图像缓存与现有画布，但无法补回缺失的资源。常见问题、运行日志与求助信息三个区域默认收起，以紧凑条目保留入口；常见问题展开后区分问题标题、排查说明与配置修复操作，配置修复结果独立呈现，保留说明原文。需要进一步求助时，展开报告区生成并预览信息，再自行复制。旧运行日志不会因配置修复被当作新的运行结果。加载期救援继续使用独立的早期恢复链路。

### ModHub 自有 AI 辅助修复

帮助中心内完成四步操作，每一步显示当前状态和下一步：

1. **描述问题**：可直接选择【猜你想问】，或填写触发步骤、实际异常与预期结果后点击【获取帮助】。推荐问题根据本次加载日志的已有诊断在本机生成，错误优先，同类合并，最多三项；没有错误或警告时不显示。选择后直接带上对应完整日志进入确认分析，不自动联网、改包或改写尚未点选的输入。长报错不静默截断，超过 4000 字时保留原文并提示精简；加载日志会单独整理，无需粘贴全部源码。
2. **确认分析**：核对分析范围、整理依据与当前服务，可展开默认收起的完整材料预览。明确文件路径、唯一对应的文件名或精确段落与 TweeReplacer 声明映射可用于自动选择相关源码；没有直接线索且全部声明文本均在限额内时，可提供选定模组的声明文本。大包无线索、尚未确定模组或包体读取失败时，先整理日志与环境供分析，不要求玩家手选文件。需要调整对象或文件时，展开【高级选项：调整分析范围】；点击【发送并分析】即为此次发送的同意，无需另勾复选框。这一步不改包；日志中的模组名只作待核对线索，具体失败原因在独立详情中保留。
3. **查看方案**：默认勾选【自动补充相关源码，持续定位】，一次确认后在已列出的模组声明范围内自动收集证据、判断修复对象并生成代码修改。轮次上限默认 5，可在【AI 连接设置】中填写正整数，或单独勾选【不限轮次】；10 轮及以上或不限轮次显示 Token 消耗提示，找到方案、没有新证据或无法确定来源时提前停止。用户无需选择责任模组或源码，已有完整只读证据可由 AI 请求重新读入作为当前修复源码；确认修复对象时仍可请求已确认目录中尚未读取的声明文件，先读取再分析，不将未读文件直接作为修改依据。显示轮次和阶段，可随时取消，范围外材料需再次确认；更多轮次可能增加服务费用。找到修改后逐项查看前后文本再决定是否应用。无法生成修改时保留具体原因、当前日志和已读源码，优先提供已有配置检查；【调整问题说明（可选）】保留为辅助入口，无需重复提供系统已收集的材料。游戏本体、内嵌模组与大文件只读片段不在代码修改范围内。关闭自动补充后，可逐轮预览和发送；排查建议不代表修复完成。
4. **重载验证**：确认应用后强制建立“AI 修复前”时间点，类型记为“自动创建”；旧版同类记录兼容显示为“自动创建”，保留已有历史数据与保护规则。原子替换所选模组包并回读核验，启禁和顺序保留。保存后等待玩家重新载入并复现原问题，可记录验证结果，或使用修复前时间点撤销；上次修复入口在重新载入后保留。

加载日志的首错提供【获取帮助】，关联模组提供【分析此问题】，把对应的完整错误原文与候选技术名带入第二步。入口仅在本机整理材料，不会自动请求 AI 或修改包体；日志中的模组名只作待核对线索。问题草稿在本次页面内存中保留，切换页签后可继续，重新载入后不保留。

设置点击保存后生效；降低保留数量先预览淘汰结果。设置、目录及无引用包体清理在同一事务中提交，失败保持原状。设置按加载器存储身份保存，不随时间点回滚。进入还原前须保存或撤销未保存设置；删除所选点与清理历史均须确认，保护中的点不能删除。旧历史继续可用。

还原恢复原始安装包、精确启禁状态、加载顺序、美化顺序及自动联动设置。游戏存档、游戏 HTML 与内嵌模组不属于还原内容，当前 ModHub 恢复工具保持启用。扫描结果中的安装、回退和移除条目显示“当前版本 / 还原后版本”，版本来自实际安装包的 `boot.json`；未安装或无法识别时明确标注，旧还原点继续兼容，不改变还原规则。恢复前展示摘要并保存当前状态，成功核对后自动重新加载；这份当前状态也可以用于撤销刚才的还原。下次游戏就绪且加载遮罩关闭后显示一次“时间点还原已成功完成”，标明目标点与日期时间、存档保留；还原前状态仍存在时提供撤销提示。成功记录与恢复记录清理原子提交，取消或失败不会生成成功提示，已有弹窗关闭后再显示。

空间不足时先安全清理可淘汰历史并重试；仍失败会暂停普通修改，只有玩家明确选择不建立还原点才继续。还原操作必须成功保存当前状态。恢复过程中刷新或中断会留下恢复记录，下次进入优先继续；未完成前暂停普通管理、自愈及自动美化同步。

还原点直接备份加载器仓库中现有的包体，无需保留手机下载目录中的原始文件。启禁列表若残留缺少包体的名称，仍会与真实包体分别保存，并在还原预览中列出：只能还原这些记录，不能补回建点时已缺失的安装包，需重新导入。APK 与浏览器都遵循这一范围；游戏 HTML 和内嵌包不在备份范围内。

正常启动隐藏救援入口。早期恢复脚本已运行时，有效加载错误、前次启动未完成或连续 60 秒无阶段、模组或文件的实际进展才显示原因和【加载遇到问题？尝试时间点恢复】；重复警告不重置停滞计时。普通异常不自动开面板或回滚，玩家主动进入面板时暂缓后续加载，关闭后继续等待。加载页面板只提供查看与还原，无历史时说明空状态。未完成恢复记录优先继续，完成前保持加载暂停。首个游戏界面就绪且加载遮罩关闭后才标记本轮启动完成。

ModHub 启用时固定在必要前置之后、普通模组之前，导入、市场安装、排序及还原均核验精确顺序；首次发现顺序错误时建立保护点并调整下一次启动顺序。玩家可以主动禁用或卸载 ModHub，必要前置也允许经依赖警告后禁用或删除；普通保存和自愈不能自动重新启用或补回已移除的 ModHub。禁用或卸载前提示：重新载入后，ModHub 的时间点还原与加载页救援将停用；需要时可通过原生模组管理器重新启用，或重新导入 ModHub 安装包。前置缺失或版本不匹配会明确提示，不自动安装第三方模组。安装完成的重载确认由最外层等待所有持久化、还原点整理及操作锁释放后统一显示一次，“稍后重载”保持市场页签。

ModHub 执行前的加载器故障、ModHub 已被禁用或卸载、主线程完全冻结及浏览器存储被清空，无法仅由模组内的恢复入口处理。保护性变更与恢复需要浏览器原生 Web Locks 支持；缺少该接口或另一个游戏窗口正在操作时，会暂停本次修改，防止跨页面覆盖。历史按真实加载器存储位置隔离；换游戏本体或内嵌模组版本时须核对兼容性，还原不会恢复游戏本体。

## 本地包体导入

【导入模组】支持 `.zip`、`.modpack` 和 `.modpack.crypt`，可混合批量选择。ModPack 使用 ModLoader 原生检查与导入接口，保留原始字节，不修改后缀或转换包体；移动端文件选择器将其显示为 BIN 文件时也可选择。原生核验失败或缺少所需解析接口时停止导入；需要密码的包体目前没有密码输入入口，请向作者获取可直接导入的版本。

市场前置按真实 `boot.name` 与 `boot.alias` 核对，例如内置 `ModLoader DoL ImageLoaderHook` 可满足 `ImageLoaderHook`。展示名称不作为前置身份依据；多个模组声明同一别名时需先手动处理冲突。原生兼容别名允许模组提供相应技术依赖，市场仍保留各模组的独立身份。例如作者确认秋枫框架支持简易框架兼容，5.1.3 清单声明了 `Simple Frameworks` 别名，计划会注明兼容提供方，无需重复安装简易框架。有真实兼容声明时不再按固定互斥规则警告；重复提供同一依赖、游戏版本及前置范围仍单独核对。市场安装身份仍按经过核验的技术名称匹配，不凭昵称或普通模组 ID 中的框架字样判断。

## 原版图片与天气报错

使用分离图片的 ModLoader 游戏本体时，需另行导入与游戏版本匹配的 `GameOriginalImagePack`；内置核心模组和 ModHub 不包含原版图片。这是游戏基础资源，不能用可选美化包替代。

若出现天气效果的 `randomInt called with invalid parameters`、`drawImage` 类型错误或 `img/misc/sky/` 资源加载失败，请先确认原版图片包已启用，再完整重新载入游戏。缺失纹理会令图片尺寸变成 `undefined` 或 `NaN`，随后产生多个云层、星空与月亮的连锁错误；只调整模组顺序不能补齐资源。

DoL 0.5.12.13 的图片包为 [`GameOriginalImagePack-0.5.12.13.mod.zip`](https://github.com/Eltirosto/Degrees-of-Lewdity-Chinese-Localization/releases/download/v0.5.12.13-chs-1.0.1a/GameOriginalImagePack-0.5.12.13.mod.zip)。升级游戏后，请将旧版原版图片包替换为对应的新包。在【模组管理】点击【导入模组】选择图片包，确认启用后点击【重新载入游戏】。其他游戏版本请从[官方发行版](https://github.com/Eltirosto/Degrees-of-Lewdity-Chinese-Localization/releases)选择对应包。

## 市场多选安装（v1.0.3）

### 按游戏版本选择安装包

单个下载、批量安装和前置选版先读取当前 `StartConfig.version`，分页读取历史版本，自动勾选匹配当前游戏的最高模组版本并展开所属分类。匹配依据包括作者声明和文件名标注；文件名仅作为参考，不标为已核验适配。没有适配声明、没有匹配候选或当前游戏版本未识别时，默认勾选同一明确安装系列中无歧义的最新可选版本，显示原因，安装前保留适配风险确认。明确声明不适配、版本未知或语言、模型、同版本主包有歧义时不自动勾选，仍可手动选择；默认选择不自动降级，也不代表游戏实测。玩家手动选择、跳过或收起所选分类后，后续读取不会覆盖操作。全部更新复用上述自动选版规则，默认版本须高于本地；缺少适配证据时继续标为未知并确认风险，人工降级及明确不适配也保留风险确认。

版本卡片直接显示主包与附属资源的用途、完整文件名及大小。能够精确配对的音频扩展显示为可选复选框，默认不安装；配对限同一发布、同一模组系列、同一模组版本与同一游戏版本，切换主包版本会清除扩展选择。单装与批量安装使用同一规则。已安装同版主包后可以补装扩展，预检仍核验所选文件，最终仅导入新增或需要更新的组件。已有同版组件保留真实本地清单；已禁用组件需要启用时会在确认计划中明确列出。全部所选组件已安装且启用时阻止重复操作。

点击下载立即打开选版弹窗并显示读取进度，取消会终止全部请求；读取失败可在原弹窗重试。完整文件名在窄屏下换行，标题与底部操作保留在视口内，长名单局部滚动。最终计划分别显示所选组件、已有前置、运行环境要求和框架冲突，真实安装包仍逐个核验身份、依赖及游戏版本。准备期间本地组件版本、依赖或启用状态变化时要求重新核对计划，取消与核验失败不会导入。

市场已安装识别使用共享身份表与内置回退。“多恋人淫啪”对应技术名 `MidsummerNightDream` 和仓库 `youmu1818/MND-Hotel`；“枯木逢春”主包对应 `deadwood-reblooms`，其音频包不会冒充主包。旧缓存与离线目录沿用这些精确映射，安装后选择“稍后重载”仍停留市场并刷新本地状态。

历史列表通过统一 Worker 的 `/mod-releases?id=<目录ID>&page=<页码>` 按需加载，每页 20 次发布，缓存有效期六小时。固定标签及指定附件只显示已核验的发布范围；上游失败时可显示标明过期的成功缓存。作者声明、文件名标注和实际游戏测试是不同证据，推荐不代表已经完成游戏实测。

选版后先依据所选版本的发布记录展示安装计划，确认前不下载包体、不安装或启用模组。确认后才下载已批准的包并核验真实 `boot.json`；包内发现新增前置或换版需求时，先确认新增下载，再核对计划变化后导入，不把最新版前置套用到历史版本。准备包累计上限为 256 MiB，超出时提示拆分批次；执行复用已核验包体。停止后续安装不会回滚此前成功的项目。

已安装且满足全部要求的前置直接复用，不再弹出选版。版本范围由加载器解析并展示为中文，例如“3.0.0及以上，低于4.0.0”，不会把较新的 5.1.3 当成满足。版本不符、来源不可用或无法映射时，可以明确选择暂不安装此前置并保留目标，风险确认会说明依赖目标、具体范围和可能无法运行；关闭窗口不等同于接受风险。实际包改变已跳过的要求时须重新确认。

统一索引继续使用 `schemaVersion: 1`，身份数据可选的 `releaseCompatibility` 按精确发布标签、可选附件名记录 `gameVersionRange`、`evidenceUrl` 和版本专属 `dependencies`；显式空依赖列表也生效。声明范围使用 ModLoader 原生格式，不能由发布日期或模组版本数字推断游戏兼容性。

1. 打开“模组市场”，点击金框主按钮“批量下载”，勾选或点击卡片空白、标题、介绍选择未安装的模组，也可使用“全选当前筛选”。卡片内按钮和主页链接继续执行原有操作。搜索、分类和排序不会清空已选项；退出多选会清空勾选。
2. 点击“下载并安装”，在汇总页逐项选择版本或留空跳过，也可浏览更早版本。列表优先推荐适配当前游戏的包；仅支持外部下载或来源已失效的模组不可多选。
3. 下载前核对计划、前置与兼容风险，确认后才下载。已安装且满足要求的前置直接复用；需要下载的前置可选版或明确跳过。实际包声明引起新增下载或计划变化时再次确认，全部核对完成后才导入或启用。具有真实兼容别名的秋枫框架可提供简易框架依赖；两个独立包同时提供该别名时提示重复提供者，其他已知冲突仍会检查，风险确认须等待 5 秒。
4. 安装按依赖顺序逐项执行。失败只阻断依赖该项的模组，独立项目继续；“停止后续安装”会等待当前操作结束，卡片“取消下载”仅取消当前下载。成功安装的项目不会回滚。
5. 完成后查看成功、失败、跳过及前置处理结果。未完成项目保留选择供重试；有实际变更时统一提示一次重载，选择“稍后重载”会留在市场页签。

“一键全部更新”也先进入选版汇总页，只预选高于本地的适配版本；可手动选择其他版本。批量安装期间请等待任务完成后再发起其他市场安装或更新。

## 目录与工具分工

- `src/`：ModHub 模组核心源码（`boot.json`、`javascript/`、`stylesheet/`、`twee/`）。
- `release/`：由 `pack.py` 生成的本地安装包（`ModHub-v<version>.zip`），按数值版本保留最近 3 版，每版一份正式包；GitHub Releases 中的历史版本永久保留。不再同步至游戏 MOD 文件夹。
- `dolmod-site/`：模组市场在线索引、身份目录与反馈中心 Worker/Pages 仓库。
- `mod-identities.json`：模组市场元数据与统一身份字典。
- `dol-mod-extractor.js`：DoL 中文 Wiki 模组列表抓取、解析与身份合并脚本。
- `test-dol-mod-extractor.js`：模组身份字典与提取器的自动化校验脚本。
- `plans/`：ModHub 功能规划、版本迭代案与验收记录。

## 验证与打包

- 核心单元测试（含依赖拓扑排序与 ModLoader 契约）：`node src/test-smart-sort.js`
- 模组身份字典测试：`node test-dol-mod-extractor.js`
- 隔离浏览器验收：`node tests/restore-browser-server.cjs`，默认读取相邻目录的 `DoL-ModLoader-0.5.12.13-v2.101.1/Degrees of Lewdity.html`，可用 `--game "游戏 HTML 路径"` 指定其他本地版本。服务仅监听本机；分别使用显示的 `/harness` 原生存储页与 `/game` 真实游戏页。测试库使用独立端口及 `modhub_acceptance_` 前缀；游戏源在内存加工，测试包不落盘。`--self-test` 会额外核验三个补丁的唯一匹配及界面入口契约。
- 打包策略测试：`python tests/test_pack.py`
- 自动化打包与单目录归档：`python pack.py`，仅输出至 `release/`，同版本重打包默认覆盖当前最新版本的正式包。

版本号以 `src/boot.json` 为准，打包脚本不自动升版；只有明确要求升级版本号时才修改版本并生成新版。若源码版本低于本地最新数值版本，脚本拒绝覆盖或重新生成该历史版本。

打包时先在 `release/` 内生成临时包，完成完整性、版本、清单和路径校验后再替换正式包。替换成功后，按版本号各数值段比较保留最近 3 个版本，每版仅一份正式包，并清理超出范围的旧包及已有对应正式包的 `ModHub-v<version>-archiveN.zip` 同版重复包；校验或替换失败时保留原包，不进行历史清理。

以上保留与清理规则仅适用于本地，GitHub Releases 历史永久保留；本地重打包不会自动更新远端 Release。
